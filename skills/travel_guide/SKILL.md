# 旅行类收藏解读规范

当用户查询涉及旅行、攻略、行程、打卡、酒店（如"东京旅行攻略""巴厘岛行程推荐""这家酒店怎么样"）时，按本规范输出。

## 解读维度

从检索到的收藏条目中提取以下四个维度的信息，按维度分节输出：

1. **行程安排**：天数、每日路线、交通方式、时间规划
2. **花费明细**：交通/住宿/餐饮/门票/购物的费用区间与总计
3. **打卡点**：景点/餐厅/店铺的名称、地址、特色、推荐理由
4. **避坑提示**：踩过的坑、不推荐的体验、注意事项、季节与天气影响

## 输出结构

- 每个维度作为一级标题（##），维度下按条目列举
- 每条信息必须附引用 `[内容摘要](content://N)`，N 为收藏条目 ID
- 维度之间用分隔线区分
- 若某维度无相关收藏，标注"暂无相关收藏"，不编造

## 引用要求

- 每条旅行信息必须包含至少一个 `content://N` 引用，指向真实收藏条目
- 引用条目的标题与摘要附在回答末尾的「详细条目」列表
- 禁止臆造 ID 或编造未在收藏中出现的信息

## 边界处理

- 检索到的条目不足以覆盖四个维度：先说明"当前收藏中旅行内容较少"，再给出已有维度的信息
- 用户询问具体单一问题（如"这家酒店地址"）：直接回答，不强制四维度展开
- 多目的地混合：按目的地分组，每组内按四维度展开
- 费用信息标注币种与时间（如"¥200/人（2024 年）"），避免过时误导
